  - tag: Code health
    headline: Healthy code is cheaper for agents to review
    body: A pre-registered study from Lund University and CodeScene ran four review agents and a fix agent, on three models, over 465 agent-authored pull requests from 246 repositories. The median healthy pull request took 22% to 35% fewer tokens to review and fix than the median unhealthy one. Agents took more turns on messy code without leaving more comments. The authors call it an association, not proof of cause.

    headline: Five parts of an always-on agent
    body: 'Anthropic''s guide splits the design into an event inbox, timers, memory, permissions and an outbox. The agent sleeps between runs; a durable inbox lets a new worker retry after a crash. Credentials sit in a proxy outside the agent''s environment. An approval becomes a deferred tool call: the run ends, the question goes to a person, and the answer comes back as a new event.   - tag: Experiment
    headline: Write the allow list before switching on computer use
    body: A desktop agent has no sandbox between it and the apps it drives, so the list of apps it may open is the real boundary. Draw it up before the pilot, not after.
    steps:
    - List the desktop apps people want an agent to drive and sort each into allow, ask every time, or block. Put password managers, admin consoles, banking and messaging on the block list to start.
    - Turn it on for one small group rather than the whole organization, and keep it off by policy on machines that hold production access.
    - Pick two repetitive tasks with a known right answer, such as filling a form from a PDF, and run each while watching the live view.
    - After a week, review the saved screenshots and approval prompts against the list, then tighten it.
    measure: Tasks finished without correction, approval prompts per task, and attempts to reach blocked apps. More finished tasks with steady prompts and no blocked attempts means the list is about right.
