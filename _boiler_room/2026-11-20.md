  body: Autopilot gets its own Entra Agent ID and a named manager. OpenAI gives each of its background agents a separate identity. Devin Bots run on separate cloud computers. Actions logged under the agent's own name can be audited and switched off.
- title: Sandboxes leak at the edges
  body: 'OpenAI''s Codex sandbox write-up names the gaps plainly: broad reads that expose secrets, DNS exfiltration, and code planted in local packages that runs later outside the sandbox. Treat the sandbox as one layer, then audit what it still lets through.'
- title: Check the checker
  body: The Claude Code team keeps review rules apart from the change under review and escalates to a person after three failed fix-and-verify attempts. A verifier the agent can edit, or that never gives up, isn't a verifier.

  - tag: Experiment
    headline: Spend an hour red-teaming your agent's sandbox
    body: 'Built from the gaps OpenAI lists for its own sandbox: before an agent runs unattended, find out what it can still read, reach and plant.'
    steps:
    - Inside the agent's default sandbox, ask it to list files outside the repository that it can read and that hold tokens, keys or passwords.
    - Check the network. If the agent can reach arbitrary domains or a cloud metadata endpoint, route it through a proxy with a domain allow-list.
    - Find writable paths that run later outside the sandbox, such as local packages, git hooks and format-on-save tools, and make them read-only to the agent.
    - Add deny rules for what you found and run the first check again.
    measure: Readable secrets and reachable domains before and after, plus permission prompts per day for a week. Fewer secrets and domains with steady prompts means a tighter sandbox that doesn't slow anyone down.
